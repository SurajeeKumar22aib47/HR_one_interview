# REVIEW.md

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Grace test is done on whole *floored minutes* (`minutes > 10`), so 09:40:01 to 09:40:59 gives 10, which is not `> 10`, and returns 0. R2 says strictly more than 10:00 in seconds. | Shift 09:30, punch-in 09:40:01: expect 10, starter gives 0. | Compare in seconds (`secs > 600`), then floor to minutes. |
| 2 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour=..)` in whatever time zone the datetime happens to be in (naive/server local), not IST. Ignores overnight shifts (punch-in after midnight is measured against the wrong day). | Server in UTC: every punch-in is hours "late" or "early". | `shift_bounds()` builds shift start/end as IST-aware instants for the *attendance date* (R1), including the next-day end for overnight shifts. |
| 3 | `compute_work_hours` | Python `round()` (float, banker's) instead of half-up; no truncation to whole seconds. | 4050 s = 1.125 h: `round` gives 1.12, R4 wants 1.13. | `Decimal` quantize with `ROUND_HALF_UP` on integer seconds. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); builds `end` as tz-aware IST but `punch_out` is naive, so subtraction raises `TypeError`; overnight shift end (next day) ignored; `fromisoformat(..).replace(hour,minute)` keeps nothing for seconds so fine, but the date used is the string date, not the shift's. | Punch out 18:40 on a 18:30 shift returns 10 instead of 0; any call crashes with a naive datetime. | `compute_overtime(punch_out, shift_end_dt)` on aware datetimes, floor to minutes, `>= 30` else 0, using `shift_bounds()` for the end instant. |
| 5 | `create_employee` | No validation (emp_code format, email, shift pattern, `shift_start == shift_end`, impossible dates); check-then-insert race, two parallel creates can both pass the `find_one`; `created_at = datetime.now()` is naive local time and is returned as a datetime, not epoch ms. | 20 parallel POSTs with the same emp_code; POST with `"joined_on": "2026-02-30"`. | Pydantic constraints from openapi.yaml, `model_validator` for the shift rule; unique index on `emp_code` and catch `DuplicateKeyError` (409); `created_at` is UTC and returned as epoch ms. |
| 6 | `list_employees` | `skip = page * page_size` skips a whole page (page 1 starts at item 21); `total` counts the whole collection, ignoring the department filter; no sort so paging is unstable; `page` / `page_size` not validated (0, negative, 1e9). | `page=1` misses the first 20 employees; `?department=X` shows the wrong `total`. | `skip = (page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `Query(ge=1)`, `page_size <= 100` (R10). |
| 7 | `punch_in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` -> 500 instead of 404. | POST with an unknown emp_code. | Explicit 404. |
| 8 | `punch_in` | `datetime.fromtimestamp(ms/1000)` and `datetime.now()` use the *server's* local zone and keep microseconds; `date` is taken from that local time, not IST (R1) and ignores overnight shifts. | Run the server in UTC: a 00:30 IST punch-in is stored on the previous date. | Convert ms -> UTC-aware datetime truncated to seconds; derive `date` with `attendance_date()` (IST, overnight aware). |
| 9 | `punch_in` | `if body.punched_at` treats `0` as "not given"; no type/range validation, so seconds, floats, strings are accepted or crash. | `punched_at: 1783312500` (seconds) is silently accepted as 1970. | `EpochMs` = strict int in `[1e11, 4.1e12]`; check `is not None`. |
| 10 | `punch_in` | `status` is any string: `ABSENT`, `LEAVE` or garbage can be created by punch-in. | POST `status: "FOO"`. | `Literal["PRESENT","WFH","ON_DUTY"]` (422 otherwise). |
| 11 | `punch_in` | Check-then-insert race: two simultaneous punch-ins both pass `find_one` and both insert (duplicate day). | Parallel identical requests give two 201s. | Unique index on `(emp_code, date)`; insert and catch `DuplicateKeyError` -> 409. |
| 12 | `punch_in` | Response returns raw datetimes (not epoch ms), adds an `id` built from `_id` (internal id must never be exposed); `work_hours`/etc. shape differs from the contract. | Response JSON contains ISO strings and `id`. | `record_out()` serialises exactly the contract fields, instants as epoch ms. |
| 13 | `list_attendance` | Loads every matching document into memory and sorts/paginates in Python (slow at 100k); sort is by `date` only (needs `emp_code` as tie-breaker); `page=0` gives a negative slice; no date validation or `date_from > date_to` check; unvalidated `status`; leaks `_id` as `id`; datetimes not converted. | 100k documents: seconds per call; `page=0`. | Sort, skip and limit in MongoDB with `(date desc, emp_code asc)`, indexes for each filter shape, validation (422), `count_documents` for `total`, `record_out()`. |
| 14 | `/health` | Always returns ok, even when MongoDB is down. | Stop MongoDB, health still says 200. | Pings MongoDB, returns 503 on failure. |
| 15 | module level | `MongoClient(...)` returns naive datetimes (no `tz_aware`); no indexes created at all; no server selection timeout. | Naive vs aware subtraction `TypeError`; `explain` shows COLLSCAN. | `tz_aware=True`, indexes created idempotently at startup (lazily retried from `/health`), `serverSelectionTimeoutMS`. |

## Looked at, decided it was fine
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct fixed offset; India has no DST.
- `load_dotenv()` with its default `override=False`: real environment variables already win over `.env`, which is what the contract asks for.
- `HTTPException(409, ...)` for a duplicate `emp_code` and the `{"status": "ok"}` body: both match the contract (the *mechanism* behind the 409 was the problem, see #5).
- Reading `MONGO_URI` / `MONGO_DB` from the environment with defaults: fine for local use, nothing secret is hard-coded.
